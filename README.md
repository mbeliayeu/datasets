# Dataset releases

Mirror a complete Hugging Face dataset repository into a GitHub Release with a manually dispatched workflow. The default dataset is [`vidore/vidore_v3_finance_en`](https://huggingface.co/datasets/vidore/vidore_v3_finance_en).

## Run the workflow

1. Open **Actions → Mirror Hugging Face dataset → Run workflow**.
2. Keep the defaults to mirror ViDoRe Finance EN, or enter another dataset ID.
3. Run the workflow. Its summary links to the published release.

| Input | Default | Purpose |
| --- | --- | --- |
| `dataset_id` | `vidore/vidore_v3_finance_en` | Hugging Face dataset ID, without the website URL. |
| `revision` | `main` | Hugging Face branch, tag, or full commit SHA. Resolved to an immutable SHA before downloading. |
| `release_tag` | blank | Optional new GitHub release tag. Blank generates a unique tag containing the dataset ID, HF commit, run ID, and attempt. An existing release is never overwritten. |
| `asset_size_mib` | `1900` | Maximum compressed part size, from 1 to 1900 MiB. |
| `max_workers` | `4` | Concurrent downloads, from 1 to 32. |

Or dispatch with the GitHub CLI:

```sh
gh workflow run mirror-hf-dataset.yml --repo mbeliayeu/datasets \
  -f dataset_id=vidore/vidore_v3_finance_en \
  -f revision=main
```

Public datasets need no secrets. For a gated or private dataset, add a repository Actions secret named `HF_TOKEN` with a Hugging Face read token that has access; gated terms must already be accepted. Releases in this public repository are public, so mirror only datasets you may redistribute. The workflow uses the built-in `GITHUB_TOKEN` with `contents: write`; no GitHub PAT is needed.

## What a release contains

The downloader uses [`snapshot_download`](https://huggingface.co/docs/huggingface_hub/guides/download#download-an-entire-repository) with `repo_type="dataset"` and no file filters. It mirrors every repository file at the resolved HF commit, including all stored subsets and splits, hidden files, dataset cards, and license files. LFS/Xet data is downloaded as actual file contents. The original file formats and relative paths are preserved; no dataset loading scripts are executed.

For ViDoRe Finance EN this includes `corpus`, `documents_metadata`, `qrels`, and `queries`, each currently containing the `test` split. Future files are included automatically.

Each release has:

- One `.tar.gz`, or numbered `.tar.gz.part0001`, `.part0002`, … files for a larger archive.
- `manifest.json`: HF dataset ID, requested revision, exact commit SHA, source file inventory and sizes, and SHA-256 hashes and sizes of archive assets.
- `SHA256SUMS`: checksums for all archive assets and the manifest.
- Release notes with source attribution and exact extraction commands.

[GitHub permits files under 2 GiB and up to 1000 assets per release](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases#storage-and-bandwidth-quotas). Parts default to 1900 MiB, with two asset slots reserved for metadata. The compressed stream is split as it is written, avoiding an extra unsplit archive on disk. A release stays a draft until every upload succeeds, with retries for failed uploads. A terminal upload failure leaves a draft to inspect or delete; rerun with the default generated tag or choose another new tag.

This is a snapshot of one HF repository revision. Datasets whose data exists only behind external URLs or is generated by a loading script need a separate materialization step; referenced external resources and other branches are not downloaded. Dataset-specific licenses and attribution requirements continue to apply.

## Download and extract

Download the **dataset archive assets**, `manifest.json`, and `SHA256SUMS` from the release. GitHub's automatically generated “Source code” archives contain the workflow code, not the dataset.

```sh
gh release download TAG --repo mbeliayeu/datasets --dir downloaded-dataset
cd downloaded-dataset
sha256sum -c SHA256SUMS

# One archive:
tar -xzf OWNER--DATASET-COMMIT.tar.gz

# Or concatenate all numbered parts in order directly into tar:
cat OWNER--DATASET-COMMIT.tar.gz.part* | tar -xz
```

Use the actual filename prefix shown in that release's notes. Numbered parts belong to one compressed archive and must be joined before extraction. The extracted directory is a local HF repository snapshot. For datasets with supported data files and card configurations, load a particular subset with `datasets.load_dataset("./OWNER--DATASET-COMMIT", name="corpus")`.

## Local use and validation

Python 3.12+ and Git are required. To prepare assets without publishing a release:

```sh
python -m pip install -r requirements.txt
python scripts/mirror_hf_dataset.py \
  --dataset-id vidore/vidore_v3_finance_en \
  --revision main \
  --work-dir dist
```

Assets are written to `dist/assets/`; notes are written to `dist/RELEASE_NOTES.md`. Use a fresh or empty asset directory for each export.

```sh
python -m unittest discover -s tests -v
```

Tests reconstruct multipart archives, check all source bytes and checksums, cover multiple subsets and splits, and verify immutable, unfiltered downloading without network access.

The workflow uses `ubuntu-latest` with a six-hour timeout. Source files plus compressed assets must fit on the runner; the script checks estimated space before downloading when source sizes are available. For larger datasets, change `runs-on` to a runner with enough storage and adjust the timeout if needed. The dataset is stored in release assets rather than committed to Git.
